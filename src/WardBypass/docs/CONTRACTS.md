# Ward Bypass: Engine-Facing Contracts

Risk: **runtime-sensitive** (Harmony patches on a private game method and on a static method shared with creature attacks; client/server authority; IMGUI overlay reading private ward state).

Baseline: Valheim **1.0.20** (network version 41, Steam build 25909357), BepInEx 5.4.23.5, HarmonyX 2.9.0.0, as recorded in `docs/evidence/baseline.json`. Verified on 2026-10-08 against `reference/decompiled/assembly_valheim` and `assembly_utils` of 1.0.17, and re-checked on 2026-10-15 by comparison with the archived 1.0.17 code (`reference/archive/1.0.17-25730771/decompiled`): 1.0.20 moves the ZDO cheat flag to the new internal `CheatUtils` (`IsCheated`/`SetCheated`, an int revision instead of a bool), bumps the save and network versions and changes drop and upgrade randomness; none of the members used here changed (`PrivateArea.cs` and `assembly_utils` are identical).

## Authority

Ward access is decided only on the acting client. `PrivateArea.CheckAccess` has no server-side counterpart: the dedicated server neither checks piece placement, removal, door and container use nor terrain edits against wards. A client-side change therefore works on vanilla dedicated servers, and other players and the server need no installation. The ward's own state (enabled flag, permitted list) is changed only through `RPC_ToggleEnabled` / `RPC_TogglePermitted`, which the ZDO owner validates against the ward's creator; this mod does not touch them.

## Ward Locator

The locator reads ward state on the local client only; it patches nothing, invokes no RPC and writes no ZDO. It sees exactly the wards the client has instantiated, which is the loaded area around the player (no server query). Private members are resolved once in `Awake()` through `AccessTools`; if any is missing the locator logs one error and stays off while the bypass keeps working. Any exception in `Update()` or `OnGUI()` disposes the locator for the session with one error. Verified on 2026-10-16 against `reference/decompiled` of the baseline.

## Not Covered

- `PrivateArea.OnObjectDamaged` still flashes the ward for everyone (`FlashShield` → `RPC_FlashShield` to `ZNetView.Everybody`) when a structure inside it is hit.
- Mods that replace ward logic (for example WardIsLove) use their own checks and are not affected.
